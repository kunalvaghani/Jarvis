## How today's Jarvis works

`Start Jarvis.cmd` → `jarvis_bootstrap.py` / `jarvis.launcher` → `main.py` → voice/text ingress (`engine.py`, `commands.py`) → `Actions.execute` → configured direct routes or the existing Brain planner → `ToolRegistry` / control / MCP adapters → independent verifiers → existing task and memory completion hooks → Island/transcript updates.

The optional BNEG path is `neural.service.BrainService` → `Registry.refresh` → `CapabilityGraph.from_registry` → `Router.route` → compiler → durable dispatcher. Its configuration is **off**. Even when enabled it only handles known compiled workflows; other requests retain the legacy fallback. Do not silently enable it or claim it is already the universal active router.

Fresh metadata: **306 neurons, 426 synapses, 148 ToolSpecs, 19 execution methods, 91 MCP tools, 12 bundled/custom skill files, 405 Python modules indexed without parse errors**. The 179 `kind=tool` neurons include methods and core control nodes; they are not 179 ToolSpecs. All 148 ToolSpecs have neurons. All 306 nodes have status `active` in the source snapshot, which does not imply permission, availability or live success. Eight have unknown side effects and must remain ineligible.
