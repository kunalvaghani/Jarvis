Read discovery_call help and the vehicle schema. Research real sources first;
retain hashed source records using existing public research/background tools.
Use Source IDs actually returned by memory; do not invent a source reference.

The current numerical adapter has an assumed double-wishbone topology derived
from BSD-licensed Chrono JSON examples. It does not reconstruct proprietary F1
internals or turn a fan model into exact engineering geometry. Explain that
limitation and every assumed mechanical/tire/aero property.

Execute `lab compare vehicle "{request}"` with a schema-valid JSON object. The
existing brain reserves resources and a non-refundable invocation slot, runs
the fixed CPU solver and independently checks raw traces/native files. No
arbitrary host script, package installation or paid call is granted by this skill.

The baseline and candidate share one immutable scenario and power unit. Only
the declared Corner Mode front-flap delta affects candidate aero coefficients.
For 2026, spatial zones drive front/rear Straight Mode together. Both modes must
actually occur. For 2025, the front-wing model remains fixed and has no active
front-wing zones. Correct invalid inputs only within the user's scope; preserve
failures, never retry an uncertain or already completed run blindly.

Use numerical maximum observed speed and mechanical engine energy honestly:
they are not verified terminal top speed, fuel energy or hybrid battery use.
Flat-terrain prescribed-control tests are not lap/track validation. Full Test A
also requires actual asset search/license/identity evidence, native visual and
functional representations, appropriate track/top-speed checks and provenance.
Report unresolved requirements rather than mark the whole task complete.
