# Workflow

Use runtime_capabilities to discover relevant tool and program references when needed. A saved app with an exact name can launch through open only when its executable/shortcut is still present or its shell ID has valid AppsFolder syntax. Installation folders are references. Multiple distinct saved launch targets need an explicit executable path. Configured app aliases take precedence over memory entries. Do not guess command arguments from a note.

Use the current installed app catalogue for native app paths. Observe the foreground window and current controls. Use available open, select, click, shortcut or scroll operations with a fresh target. An explicit ordinal is enough when the result category is clear. Ask only if the current state leaves genuine ambiguity. Historical labels are hints: never reuse control IDs, handles, coordinates or stale observations. Verify the requested state after acting.

Use only tools offered by the current Jarvis catalogue. Check current state, preserve task checkpoints and stop on cancellation. Skill guidance never expands permissions.

Native Windows controls and the owned browser's DOM tools take priority. When a named target has no accessible match, the enabled visual fallback can propose one bounded click using fresh local vision and the reviewed UI-TARS parser. It checks window identity, focus, geometry, pixels and the target region again before input, then independently observes the outcome. Model confidence is not proof. Never switch to vision after a native action had an uncertain result; ambiguous, changed or unsupported targets require fresh planning or clarification. Coordinates and handles must never become reusable procedures.
