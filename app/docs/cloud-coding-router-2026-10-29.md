## Integration

The existing `HybridGateway`, `GroqAdapter`, quota ledger and native worker are extended. Cloud models return proposals to the same local schema, file ownership, source/frozen hashes, candidate progress, atomic-write, executable-check and approval guards. They never execute tools themselves. Planning and coding stages support cloud assignment. Ordinary unapproved work remains local. Explicit task-level synthetic or approved-project provenance is mandatory; a source repository is not made cloud-safe merely by having a free account.

`coding_cloud.enabled` registers the feature; `dry_run_verified` stays false until verification gates pass. Runtime per-task `native_coding_provider` accepts local/auto/groq/gemini. Ordinary auto tasks stay local; complex approved tasks or repeated verified reasoning failures may use cloud. Deterministic scope/path/permission defects do not request reasoning escalation. Two rejected local function attempts may make one bounded cloud handoff under the original total time/repair budget; unavailable cloud cannot restart the same local loop. Each provider is limited to two failed proposals per unchanged source. No uncertain file action is replayed.

Groq coding uses non-streaming JSON-object proposals and strict local schema validation. API function calls and streaming are separate adapter modes; no incompatible structured/tool/stream combination is sent. Gemini supports REST Interactions and the currently selected generateContent transport, low/medium/high thinking, completion checks and actual usage reconciliation. GenerateContent supports text/JSON; unimplemented function mode refuses before reservation. It does not use provider-side code execution. No new inference framework or package installation was performed. Already-installed `python-dateutil==2.9.0.post0` is now declared for Windows Pacific timezone fallback.
