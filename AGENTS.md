# Jarvis repository documentation

The application is under `app/`; read `app/AGENTS.md` before changing it.

For every future project update, update `app/README.md` in the same change when features, behavior, dependencies, setup, configuration, paths, UI, integrations, limitations, or verification results change. Keep the root `README.md` overview and links consistent. If an update has no documentation impact, state that in the final report instead of adding filler.

Use repository-relative Markdown links in README files so they work after relocation and on GitHub. Include available current images for visible changes, label rendered previews and upstream reference images accurately, and preserve artwork/source attribution. Never fabricate screenshots or validation results. Date fresh results, distinguish regression/readiness checks from live feature checks, and preserve the context of historical measurements. Do not publish credentials, private recordings, or unrelated desktop content in documentation.
